# 作業環境測定士試験 過去問解説サイト

https://aoi-s-office.jp/sokuteishi/ で公開する前提の Eleventy プロジェクト。

## 使い方

    npm install
    npm run dev        # 下書きも表示してローカルで確認（http://localhost:8080/sokuteishi/）
    npm run build      # 本番ビルド（published の問題だけ。_site/ に出力）

## データを入れる流れ

1. ひっかけパターン一覧のExcelから、章・ひっかけパターンの割り当てを作る
       python tools/convert_wana.py <Excelのフォルダ> data
2. 公表試験問題のPDFから、問題文・選択肢・正答を取り込む
       pip install pdfplumber pyyaml
       python tools/import_pdf.py <PDFのフォルダ> --data data
   - ファイル名は協会の公表ファイル名のまま（EM20261803.pdf か 20260217-3.pdf の形）
   - 図は src/assets/figures/ に自動で切り出される（図の中の正答の○は白で消す）
   - 数式で文字にできない選択肢は画像になり、選択肢は「図の1」〜「図の5」になる
   - 読み切れなかった問題は import_report.csv に出る。PDFと見比べて YAML を直し、_review と _import_flags を消す
   - 根号（√）や反応の矢印（⇄）など、PDFで図形として描かれている記号は文字として取れないので、手で補う
3. explanation（解説）と、必要なら choice_notes（肢ごとの解説）を書き、status を published にする
4. git push すると Netlify が自動でビルドする

published の問題は、問題文・選択肢・正答・解説がそろっていないとビルドが止まる。
ひっかけパターンは、裏取り前（verify: true）でも公開する。誤りに気づいたら、ひっかけパターン一覧のExcelで確度に「非公開」と書いて convert_wana.py を実行し直すと、そのパターンはサイトから外れる。問題そのものを外すときは status を draft に戻す。「その他（単発）」のパターンは表示しない。

## 既存サイト（aoi-s-office.jp）からの配信

このサイトは別のNetlifyサイトとして作り、既存サイトの `_redirects` に次の1行を足して /sokuteishi/ 以下で見せる。

    /sokuteishi/*  https://<このサイトの名前>.netlify.app/sokuteishi/:splat  200

既存サイトの robots.txt に `Sitemap: https://aoi-s-office.jp/sokuteishi/sitemap.xml` を追加し、
Search Console にも同じサイトマップを送信する。

## 設定（src/_data/site.js）

- origin / pathPrefix … 公開先のドメインとフォルダ
- showStem … 問題文・選択肢を表示する（協会の許諾に基づき true）
- sourceName … 出典表示の文言（許諾の条件で指定があれば合わせる）

## 参考書のページ

`book/<章ID>.md` を置くと、`/book/<章ID>/` に参考書の章ページができ、その章に関わる問題の解説欄に
「参考書『〇-〇 …』で復習する」ボタン（新しいタブで開く）が自動で付く。章IDは data/master/book.yaml の chapters の id。

Claude Docs の原稿を Markdown で書き出したら、次で制作用の節（動画台本メモ、イラストの指示や生成プロンプト、
執筆メモ、要確認事項）を取り除いてから置く。

    python tools/clean_book_md.py <書き出したMarkdown> <章ID>

## 確認中の解説

問題データに `review_note: …` を書くと、解説欄に「現在、管理者にて確認中」の枠で表示され、
管理用の一覧ページ `/sokuteishi/review/`（メニュー・サイトマップには載らない、noindex）にまとめて出る。
確認が済んだら、解説を直して `review_note` の行を消す。

## 細かい論点（深追い不要）

試験対策として深追いする必要のない、細かい論点の選択肢には、`minor_note: …` を書く。解説欄に、目立たない文字で
「細かい論点なので、深追いは禁物です。」と表示される。管理用の一覧ページ `/sokuteishi/review/` にも載る。
この種の選択肢は、根拠の確認を後回しにする（ひっかけ・頻出のおとりの確認を先に進める）。

## ひっかけパターン一覧を更新したとき

`python tools/convert_wana.py <Excelのフォルダ> data` で変換し直す。ひっかけパターンのIDは、名前が同じパターンは前回のIDを、
名前を直した型は同じ問題に付いていた旧IDを引き継ぐので、ひっかけパターンのページのURLは変わらない。
ランクは Excel の「ランク」列の値をそのまま使う（22回版は A＝22回中5回以上、B＝2〜4回、法令は重み付き回数で判定）。

### 問題集Excelの正答の訂正

`tools/import_book_excel.py` で取り込み直すとき（`--force`）は、次の訂正を `--overrides` で指定する。
2017-02:bunseki:7=3（2018年版の正答）、2018-08:design:1=1、2018-08:bunseki:2=3、2015-02:design:17=4（問題集・試験問題の原本の画像で確認）。
また、2016-08 の一般 問1 は Excel の選択肢の並びが原本と違っていたので、取り込み直した場合は選択肢を「㋑㋩㋥㋺／㋩㋥㋑㋺／㋩㋥㋺㋑／㋥㋩㋑㋺／㋥㋩㋺㋑」、正答を 2 に直す

## 過去問マスタ（master_C1〜C4_*.json）の反映

共通科目（一般・法令・デザイン・分析）の問題文・選択肢・正答・図は、マスタ（原本の画像と照合済み）を正とする。

    python tools/apply_master.py <マスタJSONと図の画像があるフォルダ> --data data --figures <同じフォルダ>

- 表記だけの違い（空白、全角半角、LaTeX の書き方、㋑㋺の印など）は置き換えない。文字や内容が違うときだけ、マスタの文面で置き換える。
- マスタの図（`<ID>_1.png`）は `src/assets/figures/<年月>-<科目>-<問>-fig.png` にコピーして問題に付ける。
  「【図の内容（文字化）】」は図の代替テキスト（alt）に使う。選択肢そのものが絵のとき（`KEEP_FIGLABEL`）は、答えの手がかりになるので文字の選択肢にしない。
- マスタに独自に入っている注記（※…、紙面の列見出し…）は取り込まない（`SKIP_STEM` / `SKIP_CHOICES`）。
- 原本の印字（誤植）をそのまま載せている箇所は、問題の `text_note` に書く（「原文について：…」と表示される）。
- 選択科目（C5 鉱物性粉じん・C6 特定化学物質・C7 金属類・C8 有機溶剤）も、同じマスタで突き合わせる。正答が違うときはマスタに合わせる。
  分数と根号の入った式（`KEEP_FIGLABEL` の R2-1-C5-02 など）は画像のまま。表は本文の表にして、元の画像を外す。
- トップページの「このサイトについて」は `src/index.njk`、お問い合わせのURLと未掲載の回は `src/_data/site.js`（`contactUrl`、`missingExams`）。
- 第1種の放射性物質は対象外。`data/exams/*/hoshasei.yaml` に `excluded` を付け、全問を draft にしている。

## 数式（LaTeX）と図の方針

- 図の画像は、いただいた25枚（絵表示、構造式、グラフ、配置図など、文字や式で表せないもの）だけを使う。それ以外は、本文・表（Markdown の表）・LaTeX で表す。
- 問題文・選択肢・解説の中の `$…$` は、サイトのビルド時に KaTeX で HTML にする（`src/_data/db.js` の `withMath`）。
  `\frac` は読みやすいように `\dfrac` に直して表示する。フォントとCSSは `src/assets/katex/`（woff2のみ）。
- `tools/apply_master.py` は、`LATEX_CHOICES` に入れた問題の選択肢を、マスタの LaTeX のまま入れる。

## 出題頻度（選択肢ごと）

各問の解説欄に、「その科目の過去N回のうち、同じ内容が何回出題されたか（出題確率）」を、選択肢ごとに表示する。
計算問題・穴埋め・組合せ・物質名を選ぶ問題は、選択肢ではなく、問題として数える。

- 計算は `python3 tools/compute_freq.py apply`（結果は、各問の `freq` に書き込まれる）。新しい回を追加したら、もう一度実行する（分母が増える）。
- 共通科目の分母は23回、選択科目は12回（令和8年度第2回を追加すると、共通科目の分母は24回になる）。
- 同じ内容かどうかは、記述の文字の類似度（0.86以上）と、正誤の向きの一致で判定する。言い回しの違う同じ内容は、「同じ記述」とは数えず、数字と種類（第○種など）が一致し、論点が近いものを「似た記述」として、別に数える（類似度0.70以上＋ガード）。実際の頻度は、この2つの間にあることが多い。

## 問題の区分（5ランク：S・A・B・C・D）と、解法の印

問題の「ランク」は、出題頻度から決めた5つの区分（学習の優先度）。全科目で意味を統一している。
- S 得点必須（最優先）／A 得点必須／B 何とか得点：既出で、科目内の相対評価（境目は `THRESHOLDS`、目標 S15％・A25％・B30％）。トレンド（直近K回に通算の半分以上が集中）はA→S、B→Aに1段階引き上げ。消去法（おとりを全部除外／2択）や原理で絞れる問題もB以上。
- C 余裕があれば得点：既出だが過去に1回だけ（通算2回）。捨てない。
- D 失点やむなし：完全な初見（論点がその問題にしか出ていない）で、消去法・原理でも絞れない。捨てるのはDだけ。
- CとDの境目だけは絶対（既出か初見か）。選択科目のBの下限は3回（C＝通算2回）。
- 解法の印（バッジ）：暗記で解く／原理で解く／消去法で解く／トレンド／初見（`db.js` の `METHOD`）。

**判定に使う入力**：1. 論点の出題回数（`points.yaml`）、2. 共通科目のパターンの紐づけ（`book.yaml`）、3. 問題単位の回数（計算・穴埋めなど）、4. 原理の出題回数（`principles.yaml`、境目は `PR_THRESHOLDS`）。「同じ記述の回数」は表示用の参考値。

**出題傾向の変化（重要）**：共通科目は令和5年度第1回以降、正答の既出率が急落している（一般2〜4割、関係法令4〜6割。それ以前は8〜10割）。選択科目には断絶はなく、直近の既出率は5〜9割。通算の定番の統計は、共通科目では以前ほど効かない。`tools/backtest.py` の「最新2回」の表で確認できる。

**バックテスト**：`python3 tools/backtest.py` → `/tmp/backtest.md`。判定の回数はその回より前だけで数える（受験者の立場）。期待得点率はS〜Cを学習したときの目安で、サイトには載せない。

**論点マスタ**
- `data/master/points.yaml`：1論点＝1つの事実のまとまり。`id`（`pt-科目-連番`）は固定。名前・頻出テーマ・所属する選択肢（`回|問|選択肢番号`）を持つ。
- 作成・更新は `python3 tools/build_points.py --update`（Janomeが必要：`pip install janome`）。2回目以降は、既存の論点のid・名前・所属を変えず、新しい選択肢だけを、既存の論点の中心との類似度（0.62以上）で、最も近い論点に入れる（入らなければ新しい論点）。結果は、決定的（何度実行しても同じ）。
- 同じ事実と判定した選択肢の組は、`data/master/point_links.yaml`（手動）に登録すると、`--update` で、論点が統合される（`merged_into`）。
- 論点名・頻出テーマは、`points.yaml` を直接直す。関係法令は、`data/master/points/hourei.py` のルールで、初回の名前を付けた。


**改変型（関係法令・一般・デザイン）**：正答の選択肢と、文字の類似度（3-gramのJaccard 0.40以上）が近く、正誤が逆の記述が、別の回にある（過去に正しい記述として出た事実の数値や範囲を変えたもの）とき、初見（D）をC（解法の印：似た記述で解く）に上げる。`compute_freq.py` の `compute_near`、`THR_NEAR`、`NEAR_SUBJ`。令和5年度以降の関係法令のDの約4分の1が、これに当たる（バックテストでは、得点は半分で数える）。分析・選択科目では効かない（当てはまる問題がほぼ無い）ので、対象にしていない。

**原理（分析・一般・デザイン、選択科目）**：論点より広い「もとの理屈」（`data/master/principles.yaml`）。原理に紐づく論点が出た回の数（和集合）を、原理の出題回数とし、正答の頻度の、4つ目の入力にする（原理用の境目は `PR_THRESHOLDS`。分析・一般・デザイン：23回中S12・A8・B5回以上。関係法令は、令和5年度以降のDの正答で原理から導けるものが約5％（2〜3問）しかなく、原理の層を作っていない）。紐づけの基準：正答の選択肢の正誤が、その原理だけから、直接導けるときだけ（暗記が要る事実は、紐づけない）。手順：`python3 tools/extract_principles.py <科目>`（候補）→ `python3 tools/link_principles.py <科目>`（論点との紐づけ候補）→ 採用を `data/master/principle_links.yaml` に書く → `python3 tools/link_principles.py --apply` → `compute_freq.py apply`。原理のページは `/principle/<id>/`、科目ページに一覧が出る。


## 物質別の暗記リスト（特定化学物質・金属類）

ガイドブック3（特定化学物質関係）・4（金属類）の「物質別各論」の目次・本文から、物質ごとの測定方法（捕集法－分析法）の一覧を作り、その物質が登場した過去問をひも付ける。科目ページに「物質から探す」、物質ごとのページ（`/substance/<id>/`）が出る。
- 作成：`python3 tools/build_substances.py` → `data/master/substances/<tokka|kinzoku>.yaml`。入力は、OCRのXMLをページごとのテキストにした `/tmp/GB3.txt`・`/tmp/GB4.txt`（`作業環境測定ガイドブック３_…xml` のLINE要素のSTRINGを、ORDER順につなぐ。ページの区切りは `<<pN>>`）。
- 物質名・測定方法・ページは、目次から確実に取れる。捕集材・脱着液・検出器・波長は、方法の「原理」の段落から機械的に拾うので、抜け・誤りがある（ページを見て確認する）。
- 過去問との照合は、`match`（別名を含む名前）で、問題文・選択肢を検索する（`src/_data/db.js`）。物質名が、他の物質名の一部のとき（ベンゼンとエチルベンゼンなど）は、カタカナの直前・直後を除いて照合する。

**手順（新しい回を追加したとき）**：問題データを追加 → `python3 tools/build_points.py --update` → `python3 tools/compute_freq.py apply` → ビルド。

- 理由の文言は `src/_data/db.js` の `WHY`。
- 注意：区分は、過去の全回の出題にもとづくので、古い回の問題ほど、「あとの回の出題」も数に入る（カードに注意書きあり）。

## 判定の仕組みの凍結（2026年11月版）

## 参考書のカバー率（`tools/book_coverage.py`）

参考書の章立てを、数字で決めるためのツール。サイトの表示にも、区分の判定にも使わない。

- `data/master/book_map.yaml`：参考書の章と、判定の材料（原理・論点・テーマ・物質・解法の形式）との対応表。種類は、原理／テーマ／数値表／論点／物質表／解法。`status` に、`draft`／`written` を書く。`--init` で作った土台（2026年11月3日、222章）を、人が直す。
- `python3 tools/book_coverage.py --r 0.5` → `/tmp/book_coverage.md`。科目別のカバー率、章別の限界効果、未収録の論点、一般のテーマ章で拾えた数。`r` は、テーマ・数値表の章が、初見の論点を拾える割合（0〜1。1は、原文・表で完全に網羅した上限）。
- `python3 tools/book_coverage.py --check`：検算（全論点を入れた対応表の得点＝正答の論点が既出の問題数／空の対応表＝0％）。
- 採点は、`backtest.py` と同じ考え方（その回より前の出題だけ）。おとりの除外は、その回より前に3回以上出たもの（`ELIM_MIN`）か、原理の章に入っているものだけ。
- 原理の章は、正答を見て決めた紐づけを含むので、やや楽観的。
- 初期版の結果は、`docs/analysis/book_coverage_initial.md`、小さな原理の章のまとめ候補（42章）は、`docs/analysis/book_map_merge_candidates.yaml`。

## 参考書の章（2026年11月3日に、book_map.yaml に一本化）

章の正本は `data/master/book_map.yaml`（章ID＝`bk-科目-番号`。設計書を作る別チャットから受け取る）。`book.yaml` の旧い章（76章）は、書き直し前の旧原稿ページ（`book/units.md` など6本）のURLを残すためと、旧URLの転送にだけ使う。問題の `chapters:`（旧い章ID）は、もう使わない。

- 問題→章：`python3 tools/link_book_chapters.py` → `data/master/question_chapters.yaml`（p＝決め手の章、r＝関連の章）。決め手＝正答の論点が、章の論点（points／原理に紐づく論点／themes）に入っている、物質表で解ける、計算・穴埋め・組合せ問題（解法の章）。章の対応表・論点・原理・物質の表を変えたら、実行し直す。
- カードの章タグは、決め手の章→関連の章の順で先頭3つ。絞り込み（章）と章ページは、決め手の章と関連の章の全部。「参考書『…』で復習する」ボタンは、書き終えた章（`status: written` で、`book/<章ID>.md` がある章）の先頭2つ。
- 章の表示名は「題｜科目名」（同じ題の章を区別するため）。
- 章の原稿の取り込み：`python3 tools/clean_book_md.py <書き出したMarkdown> <章ID>`（メモ欄・番号つきの制作用の節・素材パックの説明を取り、`book/<章ID>.md` に書く）→ `book_map.yaml` の該当章を `status: written` → ビルド。本文の `2026-08|design|12` は、ビルド時に問題ページへのリンクになる。
- 旧URLの転送：ビルド時に `_site/_redirects`（`src/redirects.njk`）へ、旧い章（`/chapter/<旧ID>/`）→ 問題がいちばん重なる新しい章を書き出す。旧原稿のページ（`/book/units/` など）は、そのまま残し、参考書の目次の末尾に「これまでの原稿（書き直し前）」として載せる。
- 章ページの本文の説明は、原理の章は原理の説明文、ほかの章は種類ごとの一言。書き終えた章は、参考書のページを読める。

### 問題論点（ランクD以外の問題を、参考書の章・論点・原理に必ず結びつける。2026年11月4日）

- `python3 tools/build_qpoints.py`：物質名・用語を選ぶ問題、計算問題、穴埋め・組合せ問題を、『問題そのもの』を1つの論点（`qp-<科目>-<連番>`）にして、`points.yaml` に足す（同じ問題文・同じ正答＝1つ。計算問題は問題文が似ていれば同じ。キーは『回|問|0』）。既存の論点のID・名前は変えない。関係法令は、選択肢の論点と同じ規則で、頻出テーマを付ける。
- 原理との紐づけ：`link_principles.py` の候補に、問題論点も出る。採用は、基準（その原理だけで正答が導ける）で、人が決める（暗記が要るもの、SI単位の組合せなどは紐づけない）。**原理の出題回数には、問題論点を数えない**（`compute_freq.py` の `PR_EXAMS`。区分の判定を変えないため）。
- 章への収録：原理の章（自動）と、`python3 tools/assign_qpoints.py` が作る `data/master/qpoint_chapters.yaml`（章ID→足す論点。キーワードの規則）。`book_map.yaml` は書き換えない。規則に当たらないものは `/tmp/qpoint_unassigned.md`。
- 手順：`build_qpoints.py` → `link_principles.py --apply` → `assign_qpoints.py` → `link_book_chapters.py` → `unlinked_report.py`（ランクS〜Cで章が付かない問題の数。目標0）→ ビルド。
