# 新しいチャット（サイト構築側）への指示（2026年11月8日。前のサイト側チャットからの引き継ぎ）

## このチャットの役割
作業環境測定士試験の過去問解説サイト（https://aoi-s-office.jp/sokuteishi/ 、Eleventy＋Netlify、GitHubと連携）の構築・運用。別チャット（参考書執筆側）が書いた章を取り込み、公開する。**法令・告示・通達・JIS・ガイドブックの原文確認は、このチャットに一本化**する。役割の分担・用語・ランクの境目は、プロジェクトのカスタム指示に従う。

## 最初にやること
1. 添付の `sokuteishi-site.zip` を `/home/claude/site` に展開し、`docs/HANDOFF.md`（作業の全履歴。**末尾ほど新しい**）と `README.md`（データの流れ・ツール・凍結の規則）を読む。
2. `npm install` → `pip install janome pyyaml pdfplumber --break-system-packages`（**janome がないと `validate`・`unlinked_report` が止まる**）→ `npx @11ty/eleventy`（3,671ファイル）→ `python3 tools/check_site.py`（公開ページの点検。4項目すべて✓であること）→ `python3 tools/book_coverage.py --validate`（章239・エラー0）→ `python3 tools/unlinked_report.py`（章が付かない問題0）。
3. ZIPの展開・作成は、Pythonの zipfile で行う（日本語ファイル名のUTF-8フラグのため。`zip` コマンドは使わない）。

## 章を取り込む定型（毎回、この順）
`cp` → `python3 tools/clean_book_md.py <md> <章ID>` → `python3 tools/normalize_refs.py --apply`（書名の統一）→ `book_map.yaml` は**サイト側の版を正**とし、執筆側の版からは `status: written` だけを反映（文字列置換で、その章の `status: draft` を直す。YAML の再出力はしない）→ `check_book_quotes.py <章ID>` → `book_coverage.py --validate` → `link_book_chapters.py` → `unlinked_report.py` → `npx @11ty/eleventy` → `python3 tools/check_site.py` → `docs/HANDOFF.md` に追記。
- `clean_book_md.py` は、「行を作る論点：…」の行を、本文から外し、`docs/chapter_rows.md` に記録する（回数の再計算に使う）。
- **論点の束の判断**（同じ事実の言い換えか、別の事実か）は、サイト側が行う。統合は `data/master/point_links.yaml`（`links:` の中に、`subject`・`a`・`b`・`note` を追記）→ `python3 tools/build_points.py --update <科目>`。**統合の解除**は、そのリンクを削除して、同じ手順（毎回、全リンクから作り直す）。移動・分割は `points.yaml` を直接直す。**いずれも `point_splits.yaml` に記録**（記録だけで、ツールは読まない）。統合の代表は、**メンバー数が多い方**（同数のときは、後の方）。**分割・統合のあと、`book_map.yaml`・`qpoint_chapters.yaml`・`principle_links.yaml` に、統合済みのIDが残っていないか、`validate` で確認**（残っていたら、代表のIDに差し替えるか、削除）。
- 分割・統合の前に、区分を `/tmp/levels_before.json` に保存し、`compute_freq.py apply` → `level_diff.py --list` で変化を確認。
- **原理の紐づけは、`data/master/principle_links.yaml` が元データ**。直したら、`python3 tools/link_principles.py --apply`（`principles.yaml` を作り直す）。**`principles.yaml` を直接直さない**（`--apply` で消える）。原理に加える基準：その原理だけから、正誤が、直接導けること（暗記が要るものは加えない）。
- **`tools/assign_qpoints.py` を再実行しない**（`qpoint_chapters.yaml` が、別の内容で上書きされる）。`qpoint_chapters.yaml` は、直接直す。
- 次の章の選び方：`python3 tools/book_coverage.py`（`/tmp/book_coverage.md`。上位25件だけ表示。全件は、`rows[:25]` を一時的に `[:300]` にした版を、一度だけ実行）の、未執筆（draft）の章を、カバー率の落ち幅の大きい順に。原理の章と論点の章が対になるときは、原理を先に。
- 素材パック：`python3 tools/chapter_pack.py <章ID> > packs/NNN_<章ID>.md`（統合済みの論点の出題を、統合先に数える）。執筆側へのZIPには、README（前回への回答・訂正の表・次の章の指定・ランクの境目・書き方の注意）、`packs/`、`revise/`（回数を直す章の、取り込み版）、`law/`（必要な要点ファイル）、`book_map.yaml` を入れる。

## 方針（守ること）
- 用語：「パターン」「ひっかけ」「ひっかけパターン」「頻出テーマ」。ランクは S/A/B/C（「B未満」は使わない。Dは、過去に出ていない話題だけ）。
- **参考図書の書名**：`data/master/references.yaml` の表示名が正（『機器分析の実務』『デザイン・サンプリングの実務（A・B測定編 上）』『作業環境測定ガイドブック1［鉱物性粉じん・石綿・RCF］の測定の実務』など）。内部の資料番号（J-73 など）は、公開物に出さない。
- **個人情報・入手経路**：サイトに運営者の氏名は載せない。「本人提供」「提供された〜」など、提供者・入手経路が分かる表現を、公開物・執筆側への資料（`law/` の要点ファイル、README）に書かない（資料名・版・URLだけを書く）。`check_site.py` が止める。
- 原文の取得元：法律・政令・省令＝e-Gov、告示・通達＝JAISH・厚生労働省、JIS＝kikakurui.com（運営者がページの保存ZIPを提供する。規格番号に年を付けて記録。本文は写さない）、ガイドブック＝OCR出力（運営者が提供。**本文は、リポジトリに入れない**）。確認結果は `data/law/` に要点ファイルとして残す（箇条・章節の番号と要点。式がOCRで読めないときは、そのとおりに書く）。
- 原稿の過去問の参照（`2026-08|ippan|3`）と章ID（`bk-ippan-fr01`）は、サイト側がリンクに変換する。原理ID（`pr-…`）のリンク化は、未対応。**章の本文に、論点ID（`pt-…`・`qp-…`）を書かない**（`check_site.py` が止める）。
- サイト一式のZIPは、運営者の指示があるときだけ作る（`node_modules`・`_site`・`.private_terms` を除く）。
- **1つのチャットで把握できる文脈を超えそうなときは、遠慮なく、別チャットへの移行を提案する**（引き継ぐ指示と添付ファイルを一緒に示す）。
