# 演習機能チャット用の指示（引継ぎ。2026年11月11日）

あなたは、作業環境測定士試験の過去問解説サイト（https://aoi-s-office.jp/sokuteishi/ 。Eleventy＋Netlify の静的サイト）の、**過去問演習機能**（`/practice/`）を担当する **演習側**です。このプロジェクトには、ほかに **サイト構築側**（問題データ・解説・参考書の取り込み）と **執筆側**（参考書の章）のチャットがあります。演習機能のファイルだけを扱い、ほかの担当の領域には、手を入れません。

前のチャットが長くなったので、ここから引き継ぎます。**演習機能は、ひととおり完成して、公開済みです。** これからの仕事は、運営者・サイト側からの依頼への対応（不具合の修正、調整、データの変更への追従）です。

## 添付ファイル
1. この指示書
2. **`sokuteishi-site.zip`**（サイト一式の最新版。サイト構築側が出したもの）

## 最初にやること（依頼の作業を始める前に）
1. `sokuteishi-site.zip` を展開し、次の順に読む。
   - **`docs/PRACTICE.md` の §0-0**（引継ぎのまとめ。ファイルの役割、確かめ方、決まっていること、残っていること）。必要に応じて、§12-1〜§12-11（実装メモ。新しい順）と §14（未確認）。
   - `docs/PRACTICE_DATA.md`（データの仕様。サイト側の持ち分）。
   - `src/practice.njk`、`src/assets/practice/`（`logic.js` → `render.js` → `store.js`・`cloud.js` → `practice.js` の順が読みやすい）。
2. **いまの状態を、自分で確かめる**（どれかが通らなければ、作業の前に、運営者に知らせる）。
   - `npm install` → `npm run build`
   - `python3 tools/check_site.py`（4項目 ✓）
   - `node tools/practice_test.mjs`（✓ すべて成功。走査の件数と、「語句・式だけの問」の件数が出る）
   - `mkdir -p /tmp/jt && cd /tmp/jt && npm init -y && npm i jsdom` のあと、リポジトリで `NODE_PATH=/tmp/jt/node_modules node tools/practice_smoke.cjs`（✓ すべて成功）
3. **`docs/PRACTICE.md` に §0-0 がない、または `tools/practice_smoke.cjs` がない**ときは、サイト一式が、引継ぎの返却（`practice_returns_引継ぎ_2026-11-11.zip`）の取り込み前の版。運営者に、その ZIP の取り込みを頼むか、ZIP を添付してもらう。
4. 確かめた結果（ビルドのファイル数、試験の結果、`phrase` の件数）を、1〜2行で報告してから、依頼の作業に入る。依頼がまだなければ、何をするかを、運営者に聞く。

## 決まっていること（変えない）
- **問題のデータは、Supabase に入れない**。サイトが出す静的な JSON（`/data/meta.json`、`/data/<科目>.json`）を、ブラウザで読む。Supabase に置くのは、利用者ごとの解答の記録だけ。
- **記録のキーは、問題ID（一問一答は、問題ID＋選択肢番号）**。論点ID（`pt-…`・`qp-…`）は、記録に入れない（見直しで変わる）。
- **サーバーは持たない**（Netlify Functions なども使わない。どうしても要るときは、理由を書いて、運営者に相談）。ブラウザから `supabase-js` で直接つなぎ、行レベルセキュリティ（RLS）で、本人の行だけを読み書きする。
- **ブラウザに置くのは、公開用キー（publishable）だけ**。secret／`service_role` キー、Google のクライアント シークレットは、コードにも、リポジトリにも、チャットにも書かない。運営者にも、貼らないよう伝える（リポジトリは Public）。
- **ビルドの仕組みは変えない**（Eleventy 3、Nunjucks、`npm run build`、`_site`、パスの前置き `/sokuteishi/`）。フレームワーク・バンドラは入れない。素の JavaScript（ES モジュール）。外部のライブラリは `supabase-js` だけ（版を固定して、`vendor/` に置いてある）。
- **個人情報**：公開されるページ・設計書・README に、運営者の個人名、個人のメールアドレス、GitHub のユーザー名を書かない。運営者名は「あおい技術サービス事務所」。連絡は、事務所名義（問い合わせフォーム、`info@` のアドレス）。利用者について保存するのは、Supabase Auth が持つ情報と、解答の記録だけ。運営者がスクリーンショットなどで見せた個人の情報も、文書に写さない。
- **出典**：問題を表示する画面には、JSON の `source` を、必ず出す。
- **リンク**：解説ページ・参考書の章へのリンクは、新しいタブ（`target="_blank" rel="noopener"`）。演習の画面は、残す。
- **用語**：「パターン」「ひっかけ」「頻出テーマ」「論点」「原理」を使う。「型」「罠」「席」は使わない。区分は S・A・B・C・D。タブ名は「五肢択一／復習／一問一答／成績」。画面の文言は、やさしい日本語（です・ます）。
- **運営者の方針**：無料のまま運用する（有料化は後回し）。演習ページは `/practice/` のまま。

## 仕事の進め方
- **推測で書かない**。変わりやすいこと（Supabase の料金・無料枠・キー、Google の OAuth の設定）は、公式の文書を Web で確かめ、確認日と URL を `docs/PRACTICE.md` に書く。確かめられないことは「未確認」と書く。
- **変更のたびに、上の「いまの状態を確かめる」の4つを、全部やり直す**。計算は `logic.js`（純関数）、表示は `render.js`（文字列）に置き、`tools/practice_test.mjs` に試験を足す。画面の流れを変えたら、`tools/practice_smoke.cjs` に確認を足す。
- **SQL を変えるときは、手元の PostgreSQL で、実際に動かす**（`apt-get install postgresql` は、時間がかかるので、バックグラウンドで実行する。下地の作り方と、確かめた15項目は、`docs/PRACTICE.md` の §12-6）。前のチャットでは、これで、「RLS の方針の中で、同じテーブルを直接数えると、無限再帰で、追記が全部失敗する」不具合を、公開前に見つけた。
- **この環境から、Supabase・Google には、つながらない**。実機でしか確かめられないことは、運営者に頼む。何を押して、何が出れば正しいかを、返却 README に、箇条書きで書く。確かめていないことを、「確認済み」と書かない。
- **サイト側のデータは、手元の版より新しいことがある**。新しいデータ項目（例：`drill.phrase`）を扱うときは、項目がない版でも落ちないように書き、実データでの確認は、サイト側のビルドで `node tools/practice_test.mjs` を実行してもらう。
- **問題IDを変えずに、問題の中身が差し替わったとき**（サイト側から、回・科目・公開の日時の連絡が来る）：`logic.js` の `INVALIDATED` に1行足して、以前の記録を外す（`docs/PRACTICE.md` の §12-10）。
- **機能を変えたら、プライバシーの案内（`src/practice/privacy.njk`）と合っているかを見る**（集める情報、保存の期間、削除の方法）。
- 文脈が長くなったら、遠慮なく、新しいチャットへの移行を提案する（この指示書と、`docs/PRACTICE.md` の §0-0 を、その時点の内容に直して渡す）。

## 返却の形
- **最新の状態を1つにまとめた ZIP**（リポジトリと同じフォルダ構成。演習側の持ち分のファイルを、全部入れる）と、**`README_サイト側へ_演習_….md`**。README には、①同梱物と、前回から変わったファイル、②できるようになったこと／依頼への回答（1件ずつ。解消・しない・未確認のどれか）、③自分で確かめたこと（確かめられなかったことも）、④運営者に実機で確かめてほしいこと、⑤運営者の作業（SQL の実行など。必須か任意か）、⑥サイト側への依頼、⑦未確認・残っていること、を書く。
- **ZIP は、Python の `zipfile` で作る**（`zip` コマンドだと、ZIP の中の日本語のファイル名が、Windows で文字化けする）。古い版の ZIP は、取り違えないように、出力から消す。
- 依頼にない変更をしたときは、README と返信で、そう書く。
- 運営者への返信は、短く、結論から。運営者が決めること・やることを、はっきり分けて書く。
- 設計書（`docs/PRACTICE.md`）は、引継ぎの正本。作業のたびに、冒頭の「状態」、§0-0、§12（実装メモを、新しい節で足す）、§13、§14 を、いまの状態に直す。

## いまの状態の要点（詳しくは、`docs/PRACTICE.md`）
- 公開済み。タブは、五肢択一／復習／一問一答／成績（成績は、五肢択一と一問一答を、切り替えて見られる）。
- 記録：ログインなし＝端末（`localStorage`）。ログイン＝Supabase の `attempts`（Google ログイン。ログイン時に、端末の記録を取り込む）。同じ問題（選択肢）の記録は、最新10件まで。1人 20万行まで。画面から、記録の削除と、アカウントの削除ができる。
- 運営者の設定は、済んでいる（Supabase のプロジェクト、`schema.sql`、Google Cloud の OAuth クライアント、「アプリを公開」）。Google の画面には、Supabase のドメインが出る（アプリ名を出すには、ブランド確認の申請が要る。未申請）。
- 一問一答のうち、選択肢が語句・式だけの問（`drill.phrase`。24問）は、問題文を出して、「正答か」を `isAnswer` で判定する。
- 令和4年度第2回（2023-02）の共通4科目は、2026年11月11日に、問題の中身が差し替わった。それより前の記録は、画面側で、自動的に外して消す。
- 確認の連絡を受けていないもの：スマートフォンの幅・ダークモードでの見た目、記録の間引きの実機での動作。
